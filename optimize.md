# План оптимизации CPU-intensive операций

Инварианты из `ds.md`: latency ≤ 1 c, RPS 1000 (цель 2000), payload до 100k токенов,
точность ≥ 95% (span-based Levenshtein), контракт `{payload, payload_id}→{result}` заморожен,
ПД не в логи/метрики, идемпотентность по `payload_id`.

Все правки — **эквивалентные по результату** (не меняют детектируемые спаны и маски),
поэтому точность не должна измениться. Проверка — `go build`, `go vet`, `gofmt`, `go test ./...`.

## 1. masker.go:21-53 — O(n²) → O(n) однопроходный builder (приоритет №1)

**Проблема:** на каждый span пересобирается вся строка (`b.Reset()` +
`text[:s.Start]+replacement+text[s.End:]`). При 100k токенов и многих спанах — квадратично.

**Правка:** сортировать спаны **по возрастанию Start**, затем один проход:
писать `text[prevEnd:start]` + replacement, в конце `text[lastEnd:]`. Один builder, один проход.

**Важно:** заменить `sort.Slice` на сортировку по возрастанию (сейчас по убыванию).
Логика маскирования не зависит от порядка (спаны не пересекаются после `MergeSpans`),
поэтому результат идентичен.

## 2. mask/rules.go:177-198 — `MaskRules()` → package-level var

**Проблема:** аллокация map на каждый вызов `Apply`.

**Правка:** вынести в `var maskRules = map[string]func(...){...}` и использовать напрямую.
Map только читается — безопасно.

## 3. ner.go:63-89 — горутина на chunk → синхронно для 1 chunk, worker pool для многих

**Проблема:** спавн горутины на каждый chunk на каждый запрос. Для 1 chunk (типичный
случай) — чистый оверхед.

**Правка:** если `len(chunks) == 1` — вызвать `detectChunk` синхронно. Для многих chunks —
ограниченный worker pool (фиксированное число воркеров, например
`min(len(chunks), runtime.NumCPU())`), чтобы не плодить горутины при 100k токенов.

## 4. ner.go:102-122 — `chunkText` rune-конверсия (низкий приоритет)

**Проблема:** `[]rune(text)` + `string(runes[...])` на каждый chunk — двойная аллокация.

**Правка:** кириллица многобайтовая, резать по байтам нельзя без потери корректности.
Оставить rune-логику. Не трогать без необходимости.

## 5. context.go:73-110 — двойной `strings.ToLower` на span

**Проблема:** `hasContext` вызывает `strings.ToLower` окна, затем `hasStructural` — ещё раз
`strings.ToLower` того же окна.

**Правка:** вычислить `window := strings.ToLower(text[start:end])` один раз в `hasContext`,
передать в `hasStructural` (и `hasOrgMarker`). Экономия 1 аллокации на каждый NER span.

## 6. processor.go:108-113 — `tokenCount` без аллокаций

**Проблема:** `strings.Fields` аллоцирует slice + подстроки на каждый запрос (в т.ч. cache-hit).

**Правка:** byte-цикл по пробелам/табам/новым строкам, считая слова. Ноль аллокаций.

## 7. crypto.go — кэшировать derived key + cipher/GCM

**Проблема:** `deriveKey` (SHA-256) + `aes.NewCipher` + `cipher.NewGCM` на каждый
encrypt/decrypt. Ключ константен.

**Правка:** в `Store` кэшировать `cipher.AEAD` (GCM) один раз при создании.
`encrypt`/`decrypt` принимают готовый AEAD. Нонс по-прежнему генерируется на каждый
вызов (обязательно для безопасности).

## 8. stats.go:104-121 — триммить `window`

**Проблема:** `window` растёт неограниченно → memory leak + O(n) в `Snapshot`.

**Правка:** в `RecordTokens` после append отбрасывать записи старше 1 секунды (или держать
кольцевой буфер фиксированного размера). `Snapshot` уже считает RPS по последней секунде —
тримминг не меняет результат.

## 9. processor.go:68-75 + ratelimit.go — уменьшить критическую секцию

**Проблема:** `bucketMu` сериализует все запросы через `adjustBucket` (Redis `KEYS` при
истечении кэша).

**Правка:** `adjustBucket` уже кэширует `AliveCount` на `ttl/2`. Достаточно: не держать
`bucketMu` во время Redis-вызова — сначала получить `n` вне лока, потом под локами обновить
bucket. Либо вынести `adjustBucket` из-под `bucketMu` (bucket сам потокобезопасен через свой
`mu`). Это снижает контеншн.

## 10. structural.go — regex-оптимизации (рискованно, делать аккуратно)

**Проблема:** 12 полных regex-проходов + повторные marker-сканы на каждый match.

**Правка (эквивалентные):**
- `cardRe` (`structural.go:19`) — `(\d{4}[\s-]?){3}\d{4}` — вложенный квантор. Заменить на
  явный `\d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}`. Эквивалентно.
- `strings.Map` в `CardDetector` (`structural.go:155-160`) — заменить на in-place byte-цикл
  без аллокации.

**НЕ трогать:** `passportRe`, `phoneRe` (высокий риск для точности 95%).

## Порядок выполнения

1. **Безопасные (1, 2, 6, 7, 8)** — низкий риск, сразу.
2. **NER/context (3, 5)** — средний риск, после безопасных.
3. **ratelimit (9)** — низкий риск.
4. **regex (10)** — только `cardRe` + `strings.Map`.
